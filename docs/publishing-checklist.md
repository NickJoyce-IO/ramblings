# Publishing Checklist

Work through this for every Post before publishing. Once every item is true, add `checklist: passed` to the Post's frontmatter. The build fails for any published Post without it. Drafts (`draft: true`) are exempt.

This is a personal blog. Views are my own, and nothing here speaks for my employer.

## Before you publish

- [ ] **No names.** No systems, products, suppliers, programmes, teams or colleagues from my department, and nothing that identifies them.
- [ ] **Nothing non-public.** No unreleased policy, plans, contracts, incidents, security detail, or internal figures and dates.
- [ ] **Generalised.** It describes a pattern or a lesson, not a specific live project. Examples are made generic or made up.
- [ ] **No commentary on government policy or ministers.** It stays consistent with civil service impartiality.
- [ ] **Nothing sensitive in code or screenshots.** No credentials, internal URLs or internal tooling visible.
- [ ] **My department's policy.** It complies with the current outside-publishing and social media policy, and I have sought any sign-off that policy requires for this Post.
- [ ] **My own time.** Written in my own time, on my own equipment.
- [ ] **My own words.** The prose is mine. Where AI helped beyond editing, [How This Is Made](../src/pages/how-this-is-made.astro) says so.
- [ ] **Second read.** I have read it once more as a stranger would, asking: could this embarrass me, or my employer, if quoted alone?

If any item is not true, fix the Post or leave it as a draft.
